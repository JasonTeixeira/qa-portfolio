# フィンテックプラットフォームを一人で構築：185テーブル、69API、7システム

ほとんどのエンジニアは一度に1つのサービスに取り組みます。私はエコシステム全体を構築しました。

Nexuralプラットフォームは、私のトレーディングコミュニティ向けのダッシュボードというシンプルなアイデアから始まりました。それが185のデータベーステーブル、69のAPIエンドポイント、Stripe課金、AI搭載Discordボット、リサーチエンジン、ニュースレタースタジオ、リアルタイムアラートシステムを備えた本格的なフィンテックプラットフォームへと成長しました。

私はそのすべてを設計し構築しました。以下がその学びです。

関連システム：[プロダクトサーフェスとシステムマップの構築](/blog/build-a-product-surface-and-system-map)では、同じサーフェス/システムパターンを反復可能なビルダーフレームワークに変換する方法を解説しています。

## スコープ

7つの相互接続されたシステム：
1. **トレーディングダッシュボード** — リアルタイム市場データ、チャート、ポートフォリオ追跡
2. **Discord AIエンジン** — 30以上のコマンド、GPT-4o統合、自動モデレーション
3. **リサーチエンジン** — 71以上の指標、戦略分析、CSVインポート
4. **アラートシステム** — NinjaTrader 8統合、.NETバックエンド、リアルタイム通知
5. **ニュースレタースタジオ** — 自動コンテンツ生成と配信
6. **戦略トラッカー** — トレーディングシステム全体のパフォーマンス監視
7. **自動化スイート** — 61のテストスイート、CI/CD、品質ゲート

## 大規模データベース設計

185テーブルは気が遠くなるように聞こえます。鍵は段階的な設計でした：

- **フェーズ1（コア）：** ユーザー、認証、サブスクリプション — 20テーブル
- **フェーズ2（トレーディング）：** 銘柄、ポジション、シグナル — 35テーブル
- **フェーズ3（コミュニティ）：** Discord統合、モデレーションログ — 25テーブル
- **フェーズ4（分析）：** 指標、レポート、テレメトリー — 30テーブル
- **フェーズ5-7：** リサーチ、アラート、ニュースレター — 75テーブル

各フェーズには独自のマイグレーション、テストスイート、ロールバック計画がありました。一度に複数のドメインを変更することは決してありませんでした。

### 重要だったスキーマ設計の判断

**重要な箇所は正規化：** User → Subscription → Planは完全に正規化されています。課金バグを生むような非正規化のショートカットはありません。

**速度が重要な箇所は非正規化：** トレーディングダッシュボードは非正規化されたビューをクエリします。トレーダーは3NFを気にしません — 彼らが気にするのは50ms未満の読み込み時間です。

**すべてのテーブルに行レベルセキュリティ：** すべてのテーブルにSupabase RLSポリシーを適用。APIにバグがあっても、ユーザーが他のユーザーのデータを見ることはできません。
