# SEOはブログカレンダーではなく、エンジニアリングシステムである

投稿数を増やすことはSEOシステムではない。

それは活動に過ぎない。

真のSEOシステムとは、技術的な健全性、コンテンツアーキテクチャ、証拠となるアセット、内部リンク、測定、そして配信が連携して機能するものである。

これはマーケティングというより、エンジニアリングに近い。

:::system-diagram title="SEOオペレーティングシステム" label="クロール → コンテンツ → コンバージョン" nodes="技術,意図,証拠,経路"
技術的な健全性によりサイトがクロールされる。検索意図が各ページに役割を与える。証拠がページを信頼できるものにする。経路設計が注目を、購入者、構築者、購読者への道筋へと変える。
:::

## 技術的な健全性が最優先

ページが遅い、ブロックされている、重複している、薄い、クロールしにくい場合、コンテンツを増やしても問題は解決しない。

ベースラインには以下を含めるべきである：

- 有効なメタデータ
- 正しいcanonicalタグ
- クリーンなサイトマップ
- 重要なページをブロックしないrobots.txt
- マネーページへの内部リンク
- Core Web Vitalsの予算
- モバイルファーストのレイアウト
- 表示コンテンツと一致するスキーマ

これは華やかな作業ではない。基盤となるレイヤーである。

## 各ページに一つの役割を

ブログページがあらゆるAI関連フレーズでランクインしようとするべきではない。

サービスページがあらゆる概念を教えようとするべきではない。

ケーススタディが汎用的なランディングページになるべきではない。

一つのページに、一つの意図。

例：

- `/services/ai-implementation-consulting` は、どのAIを構築すべきか判断するための支援を求めている人にマッチするべきである。
- `/work/nexural` は、本格的なフィンテック製品を構築・運用できる能力を証明するべきである。
- `/academy` は、運用モデルを学びたい構築者を誘導するべきである。
- `/tools/route-finder` は、訪問者を診断し、適切な経路へ導くべきである。

## 証拠こそがコンテンツである

最も強力なコンテンツアセットは意見ではない。

それらは証拠である：

- スクリーンショット
- 図表
- スキーマ
- テスト出力
- 成果物
- 公開リポジトリ
- 実際の指標
- 実装ノート

これらのアセットはコンテンツをより有用にし、コンバージョンを強化する。

:::scorecard title="SEOアセット品質" label="評価基準"
| アセット | 弱いバージョン | 強いバージョン |
| --- | --- | --- |
| ブログ | 意見記事 | 情報源に基づくガイド |
| サービスページ | 曖昧な提案 | 経路 + 図表 + 証拠 |
| ケーススタディ | ストーリーのみ | 表面 + システム + 指標 |
| ツール | フォームによる情報収集 | 有用な出力を伴う診断 |
| ニュースレター | まとめ記事 | 構築から学べるシステム |
:::

## 配信はシステムの一部である

Googleは新しいページにトラフィックを保証するわけではない。

公開後、ページには以下が必要である：

- 古いページからの内部リンク
- サイトマップの送信
- ニュースレターでの紹介
- LinkedIn/Xでの再利用
- 関連コミュニティ/リソースへのアウトリーチ
- UTMトラッキング
- Search Consoleでのレビュー

ここで、ほとんどのコンテンツシステムは規律を失う。

:::checklist title="公開後チェックリスト" label="配信"
- 少なくとも5つの関連する既存ページから内部リンクを追加する。
- サイトマップを送信するか、Search ConsoleでURLを検査する。
- ニュースレターで一つの角度から紹介する。
- LinkedInに一つの投稿をする。
- Xに一つのスレッドを投稿する。
- URLを被リンク/アウトリーチトラッカーに追加する。
- 14日後と30日後にインプレッションとクリックを確認する。
:::

## SEOは収益へと導くべきである

トラフィックは最終状態ではない。

最終状態は経路である：

- スタジオの購入者
- アカデミーの学習者
- ニュースレターの購読者
- 診断リード
- 将来の証拠アセット

ページが訪問者をどこか有用な場所へ導かないのであれば、それは完成していない。
