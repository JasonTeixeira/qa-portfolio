# AIネイティブスタジオが実際に作るもの

AIネイティブスタジオは、プロンプト販売所ではない。

チャットボットを付けただけのデザインエージェンシーでもない。

「AI変革」スライドを書くコンサルタントでもない。

有用なスタジオは、次の3つのレイヤーを同時に構築する：

1. ユーザーが触れるプロダクト
2. その下にあるオペレーティングシステム
3. 成果を複利効果にする成長と測定のループ

それがSage Ideasのモデルである。

:::system-diagram title="AIネイティブスタジオモデル" label="表面 → システム → 成長" nodes="プロダクト,AI,証明,成長"
プロダクトは目に見える表面である。AIは、実際のデータ、ワークフロー、権限、測定に接続されて初めて有用になる。そして証明が成長資産となる。
:::

## プロダクトの表面

表面とは、購入者、ユーザー、顧客、チームメンバーが実際に体験するものである。

SaaSプロダクトの場合、それはオンボーディング、課金、ダッシュボード、設定、サポートフローかもしれない。

社内AIシステムの場合、それはSlackアシスタント、管理キュー、レビューダッシュボード、承認ワークフローかもしれない。

ブランド・成長システムの場合、それはホームページ、サービス一覧、コンテンツエンジン、診断ツール、アカデミーファネルかもしれない。

表面はプレミアムに感じられなければならない。なぜなら人々はそれを通じてシステムを判断するからだ。

しかし表面はプロダクトのすべてではない。

## その下にあるシステム

システムこそ、ほとんどのエージェンシーが失敗する部分である。

AI機能はデモで応答するからといって本物ではない。次の要素を持って初めて本物になる：

- ソースデータ
- 権限
- 評価（evals）
- コスト制限
- リトライロジック
- 人間によるレビュー
- 可観測性
- フォールバック動作
- ドキュメント

だからこそSage Ideasのサイトは「表面⇄システム」パターンを使っている。飾りではない。仕事を販売し構築するための実際の方法なのだ。

:::proof-note title="Sage Ideas内部の実際の証明" label="証拠"
Nexuralは185のデータベーステーブル、69のエンドポイント、Stripe課金、Discord AI、実際のプロダクトスクリーンショット、アーキテクチャ図、証明ボードとともに提示されている。これらこそ、真剣な購入者がテクニカルスタジオに期待すべき証拠の類である。
:::

## 成長ループ

成長ループこそ、仕事が機械へと変わり始める部分である。

出荷されたすべてのプロダクトは、新たな証明を生み出すべきである：

- スクリーンショット
- ケーススタディ図
- 技術的分解（テクニカルティアダウン）
- 改善前後のワークフロー
- メトリクス
- 再利用可能なテンプレート
- コースモジュール
- 診断質問

これらのアセットは、SEOページ、ニュースレター記事、アカデミーレッスン、セールスイネーブルメント、ルートファインダーロジックになり得る。

これこそ、コンテンツをプロダクトと別物だと偽ることなく、1つの構築が10の配信アセットになる方法である。

:::scorecard title="スタジオが実際に出荷するもの" label="スコアカード"
| レイヤー | 良い成果 | 悪い成果 |
| --- | --- | --- |
| プロダクト | ユーザーが検査できる動作する表面 | モックアップのみのプレゼンテーション |
| AI | 評価でゲートされたワークフロー | プロンプトデモ |
| ブランド | 明確なオファーとルート | きれいな言葉 |
| 成長 | 検索と育成のシステム | ランダムな投稿 |
| 証明 | 証拠とケース図 | 偽の testimonial |
:::

## 購入者はルートを素早く知るべきである

プレミアムなスタジオサイトは、訪問者を素早くルーティングしなければならない。

通常、3つの訪問者タイプがいる：

- スタジオにシステム構築を依頼したい購入者
- まず診断を希望する運営者
- アカデミーを通じて学びたいビルダー

ホームページ、サービス一覧、ブログ、アカデミー、ルートファインダーは、これらすべての人を適切なパスへと導くべきである。

:::checklist title="AIネイティブスタジオページチェックリスト" label="ルートロジック"
- 最初の画面は、営業電話なしでオファーを説明する。
- サービス一覧は、購入者の状態と次のアクションを明示する。
- 実績ページは、表面とシステムの証明を示す。
- ブログ記事には、スタジオ、アカデミー、診断へのルートを含める。
- 主張は、実際のプロジェクト、スクリーンショット、ドキュメント、公開された仕事によって裏付けられる。
:::

## 基準

基準はシンプルである：

AIを魔法として売るな。

それが動かすビジネスシステムを売れ。

プロダクトを見せよ。

アーキテクチャを見せよ。

証明を見せよ。

そして購入者を適切な次のステップへルーティングせよ。
