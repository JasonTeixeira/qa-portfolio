# SEO 是工程系统，而非博客日历

发布更多文章并非 SEO 系统。

那只是活动。

真正的 SEO 系统需要技术健康、内容架构、证据资产、内部链接、度量和分发协同运作。

这更接近工程而非营销。

:::system-diagram title="SEO 操作系统" label="爬取 -> 内容 -> 转化" nodes="技术,意图,证据,路径"
技术健康让网站能被爬取。搜索意图赋予每个页面一个任务。证据让页面可信。路径将注意力转化为买家、构建者或订阅者的通道。
:::

## 技术健康是首要前提

如果页面加载缓慢、被屏蔽、内容重复、单薄或爬取混乱，发布更多内容也无济于事。

基线应包含：

- 有效的元数据
- 正确的规范链接
- 清晰的站点地图
- 不屏蔽重要页面的 robots 配置
- 指向核心页面的内部链接
- Core Web Vitals 预算
- 移动优先布局
- 与可见内容匹配的结构化数据

这不是光鲜的工作。它是基础层。

:::proof-note title="当前 Sage Ideas 关卡" label="CWV"
该网站现在有一个 CWV 预算报告器，它读取 Lighthouse 摘要并生成最新的预算报告。目标是在发布视觉密集型版本之前，确保公共路由的性能、可访问性、最佳实践、SEO、LCP、CLS 和 TBT 预算达标。
:::

## 每个页面只承担一个任务

博客页面不应试图为所有 AI 相关短语排名。

服务页面不应试图讲解所有概念。

案例研究不应变成通用落地页。

一个页面，一个意图。

示例：

- `/services/ai-implementation-consulting` 应匹配那些寻求帮助以决定构建何种 AI 的用户。
- `/work/nexural` 应证明构建和运营严肃金融科技产品的能力。
- `/academy` 应引导想要学习运营模式的构建者。
- `/tools/route-finder` 应诊断访客并为其规划路径。

## 证据即内容

最强的内容资产不是观点。

它们是凭证：

- 截图
- 图表
- 架构图
- 测试输出
- 制品
- 公开仓库
- 真实指标
- 实现笔记

这些资产让内容更有用，转化效果更强。

:::scorecard title="SEO 资产质量" label="评分标准"
| 资产 | 弱版本 | 强版本 |
| --- | --- | --- |
| 博客 | 观点文章 | 有来源支持的指南 |
| 服务页面 | 模糊的提案 | 路径 + 图表 + 证据 |
| 案例研究 | 仅故事 | 表面 + 系统 + 指标 |
| 工具 | 表单收集 | 带有有用输出的诊断 |
| 新闻通讯 | 汇总 | 从构建中教授的系统 |
:::

## 分发是系统的一部分

谷歌并不欠新页面流量。

发布后，页面需要：

- 来自旧页面的内部链接
- 站点地图提交
- 新闻通讯推送
- LinkedIn/X 平台二次利用
- 相关社区/资源外联
- UTM 跟踪
- Search Console 审查

这是大多数内容系统失去纪律的地方。

:::checklist title="发布后检查清单" label="分发"
- 从至少五个相关的现有页面添加内部链接。
- 提交站点地图或在 Search Console 中检查 URL。
- 发送一期新闻通讯角度。
- 发布一篇 LinkedIn 帖子。
- 发布一条 X 线程。
- 将 URL 添加到反向链接/外联跟踪器。
- 在 14 天和 30 天后检查展示次数和点击次数。
:::

## SEO 应引导收入

流量不是终点。

终点是一条路径：

- 工作室买家
- 学院学习者
- 新闻通讯订阅者
- 诊断线索
- 未来证据资产

如果页面没有将访客引导到某个有用之处，那它还未完成。
