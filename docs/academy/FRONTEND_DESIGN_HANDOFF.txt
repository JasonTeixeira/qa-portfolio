1. PRODUCT IDENTITY & POSITIONING
===============================================================================

NAME:            Sage Academy  (brand: Sage / sageideas.dev)
CATEGORY:        Engineering-judgment & career-mastery platform (not a tutorial site)
ONE-LINER:       "Learn to think like a senior engineer — and prove it."
THE PROMISE:     You don't finish with notes. You finish with inspectable EVIDENCE
                 a reviewer, interviewer, or staff engineer trusts.

THE WEDGE (why this exists):
  Tutorials teach syntax; they don't teach JUDGMENT — framing an ambiguous problem,
  routing a diagnosis, mapping a system, deciding under tradeoffs, and PROVING it
  under a skeptic's eye. Sage Academy is a judgment-and-proof factory. Every lesson
  ends in a reviewable artifact, a real failure you repair, and proof you can defend.

THE THROUGH-LINE (repeat everywhere — this is the spine of the whole product):
  FRAME → ROUTE → MAP → DECIDE → PROVE → REVIEW → REPAIR → SPACE → TRANSFER → PACKAGE
  (This is the "Sage Learning Operating System" / the mastery loop. Course 00 teaches
   it; every other course is an instance of it. Surface it as the product's signature.)

VISUAL DIRECTION:  Editorial dark-luxury. Institutional, premium, serious-but-warm.
                   Think a quant research desk crossed with a fine magazine — not a
                   playful bootcamp, not a corporate LMS. Confidence over decoration.

TONE OF VOICE:     Sharp, warm, opinionated, zero filler. Every sentence earns its
                   place. "Prove it — no vibes." Never hype; always specific.

===============================================================================

PRIMARY LEARNER:  Engineers (junior→senior) who can code but want senior JUDGMENT,

4. THE DESIGN SYSTEM  [LIVE — MATCH EXACTLY]
===============================================================================
The app already ships an editorial dark-luxury token system (CSS custom props,
prefix `--ac-`). The redesign MUST use these so the built front-end drops in.

TYPOGRAPHY:
  Display / headings ...... "Fraunces" (serif, high-contrast, editorial)   var(--ac-font-display)
  Body / UI ............... "Hanken Grotesk" (humanist sans)               var(--ac-font-body)
  Code / mono / data ...... "JetBrains Mono"                               var(--ac-font-mono)
  Scale: fluid clamp() steps; hero display very large, tight leading; body 16–18px.
  Rule: scale CONTRAST carries hierarchy (huge serif head over quiet mono kicker).

COLOR (oklch, dark-luxury base):
  --ac-bg            near-black charcoal (page)          ~oklch(15% ...)
  --ac-surface       elevated panel                      slightly lifted
  --ac-ink           primary text (bone/off-white)       ~94% L
  --ac-ink-soft      secondary text                      ~80% L
  --ac-ink-faint     tertiary / captions                 ~64% L
  --ac-accent        focus / primary action (blue)       the brand accent
  --ac-accent-text   accent text on dark
  --ac-success/-mastery  green (truth / mastery)
  --ac-danger        red (risk / blast-radius / error)
  --ac-pending       amber (in-progress / warning)
  --ac-rule / -rule-strong  hairlines & dividers
  Semantic tone system (used in all diagrams/visuals):
    accent = focus/suspect · warning = risk/blast-radius · success = source-of-truth
    · muted = out-of-scope · default = neutral. Color carries MEANING, not decoration.

DEPTH & TEXTURE:
  Layered surfaces (--ac-elev-1/-2), hairline borders, subtle grain (.ac-grain),
  restrained shadow (--ac-shadow). Atmosphere over flatness. No heavy neumorphism.

MOTION:
  Compositor-only (transform/opacity/clip-path). Easing var(--ac-ease-out-expo)
  cubic-bezier(0.16,1,0.3,1). Durations --ac-dur-fast/-normal. ALWAYS honor
  prefers-reduced-motion (meaning must never live only in motion). Reveal-on-scroll
  staggers; edges "draw in" along flow; nodes fade-up in dependency order.

RADIUS / SPACING:
  One spacing rhythm (space-xs…section), one radius scale, one elevation scale.
  Deliberate rhythm — NOT uniform padding everywhere. Grid-breaking editorial
  composition where it earns attention.

ANTI-TEMPLATE MANDATE:
  Do NOT ship default card grids, stock hero + gradient blob, or unmodified library
  defaults. Every surface shows: scale-contrast hierarchy · intentional rhythm ·
  depth/layering · typographic character · semantic color · designed hover/focus/
  active states · editorial/bento composition where it fits · motion that clarifies.

6. THE LESSON ANATOMY  [LIVE]   (what a "lesson" is — design the player around it)
===============================================================================
Every lesson is a deliberate 14-block arc (visual-first, prose to strict budgets):
  1  sprint-contract  the outcome + the proof + what NOT to claim (scannable card)
  2  mission          a vivid stake (1–2 sentences)
  3  context          why it matters (≤2 sentences)
  4  pretest          productive-failure question → "oh!" reveal
  5  concept          ONE mental model (≤40 words) + paired hero visual
  6  DIAGRAM          hero: the system/flow/structure
  7  CODE-WALKTHROUGH hero: real code/artifact, stepped
  8  COMPARE          hero: weak vs gold
  9  callout          the pro insight / standards grounding (e.g., SWEBOK, OWASP, WCAG)
  10 quiz             one sharp check + explanation
  11 verification     "prove it — no vibes": concrete confirmable items
  12 teachback        say it back in your own words (Feynman)
  13 transfer         a real application elsewhere
  14 spaced-review    seeds the recall schedule (1/3/7/30 days)
  (+ some lessons: lab (in-browser Python), debug (find+fix a real bug), tradeoff,
   calibration (weak/passing/excellent bar), unlock-gate.)

THE RUNNING ARTIFACT: across a course, the learner grows ONE artifact (e.g., a
decision memo / evidence packet). Design the player to surface "your artifact so far."

7. THE MASTERY LOOP & METRICS  [LIVE + DESIGN]   (the heart of the dashboard)
===============================================================================
This is what makes the members experience "ultimate" — surface the LEARNING SCIENCE
as a live cockpit, not a progress bar. Real mechanics in the platform:

  MASTERY SCORE WITH CAPS [LIVE]:  A lesson/course score is not an average — it's
    CAPPED by its weakest load-bearing dimension. A failed PROOF caps you (e.g., at
    78) no matter how good the rest is. Design a "cap meter" that shows the ceiling
    and WHY (which dimension caps you) + the one repair that lifts it. (Component
    already exists: ScoreCapMeter / StateBadge.)
  EVIDENCE / PROOF [LIVE]:  Learners produce reviewable artifacts ("evidence
    events"). The dashboard shows an EVIDENCE LEDGER — claim → artifact → verdict.
  IN-BROWSER LABS [LIVE]:  Real Python labs (Pyodide) with a starter + a real check
    (starter fails; correct solution passes). "A guaranteed win" per lesson.
  SPACED REVIEW / RECALL [LIVE]:  FSRS-style recall queue (1/3/7/30d). The dashboard
    surfaces "due for recall today" — retention as a first-class metric, not a nag.
  GAMIFICATION [LIVE]:  XP, streaks, and LEAGUES with promotion/relegation (a
    weekly-XP standing with a "drop line" / relegation stake). Celebration moments
    (CelebrationToast) on real wins. Momentum without cheapening the rigor.
  CERTIFICATES [LIVE]:  Auto-issued on genuine completion (verifiable code/URL).

METRICS TO SHOW THE LEARNER (the cockpit gauges):
  - Mastery score (with the CAP + the capping dimension + the lift)
  - Course/module/lesson progress (real, from completions)
  - Streak (days) + weekly XP + league standing (rank vs drop line)
  - Recall due today (retention health) + retention % over time
  - Evidence artifacts produced (the portfolio count)
  - "Next best action" (the single highest-leverage next step — see dashboard spec)
  - Time-to-outcome (est. minutes to the next proof/certificate)

DESIGN PRINCIPLE: every number must imply an ACTION. A cap meter shows the repair;
a recall count opens the queue; a league rank shows the XP to stay safe. No vanity
metrics — this is a decision instrument, matching the product's own doctrine.

10. MEMBERS DASHBOARD — "THE LEARNING COCKPIT"  [DESIGN, bound to LIVE data]
===============================================================================
Not a course list with a progress bar — a decision instrument for the learner's
growth. Editorial dark-luxury, bento/grid-breaking, every gauge implies an action.

TOP BAR: greeting + current streak (flame, days) + weekly XP + league badge +
  "recall due: N" pill (opens the recall queue). Avatar → profile/evidence.

PRIMARY PANEL — "NEXT BEST ACTION" (the single most important element):
  One card that computes the highest-leverage next step and makes it one click:
   - If recall is due → "Recall 4 concepts (6 min) — keep your retention above 90%."
   - Else if a lesson is mid-progress → "Continue: Backend · Idempotency (Step 3/6)."
   - Else if a mastery cap is lifting-able → "Repair your PROOF on Lesson 10 to lift
     78 → 91." (deep-links to the exact block.)
   - Else → "Start the next lesson in your active course."
  Show the est. time + the outcome. This is the product's "one arrow."

CONTINUE LEARNING: the active course with a live module map (done/current/todo),
  the running ARTIFACT preview ("your decision memo so far"), and resume CTA.

MASTERY PANEL: the ScoreCapMeter per active course — the ceiling, the CAP dimension,
  and the one repair that lifts it. Honest scoring made visual (this is a signature).

EVIDENCE LEDGER: the learner's artifacts (claim → artifact → verdict), count, and a
  "share portfolio" action (→ /academy/u/[handle]). The tangible outcome.

MOMENTUM: streak calendar, weekly XP trend (SageViz), league standing with the drop
  line + "XP to stay safe." Celebration on real milestones (not participation).

RETENTION: recall queue health — due today, upcoming, retention % curve (SageViz).
  "Learning that holds under pressure."

TRACKS / CATALOG: your tracks with progress rings; explore/enroll more; ⬜ coming-soon
  courses framed as roadmap, with "notify me."

CERTIFICATES: earned + in-progress (with the exact proof remaining to earn each).

LAYOUT: bento grid — Next-Best-Action is the largest tile (hero); Continue + Mastery
  are secondary; Evidence/Momentum/Retention are the supporting row; Catalog +
  Certificates below. Responsive: single column on mobile, Next-Best-Action first.

STATE HANDLING: design the empty/first-session state (no data yet → "start Course 00")
  and the returning state (rich cockpit). The first session must feel like a guided
  first win, not an empty dashboard.

VERIFICATION / MASTERY: the "prove it" checklist → mastery score with caps → the
  repair path if capped. Certificate on genuine completion (verifiable code).

SPACED RECALL (/academy/recall): a focused, low-friction queue — one prompt at a
  time, quick grade, FSRS reschedule. Feels like 6 minutes, not homework.
