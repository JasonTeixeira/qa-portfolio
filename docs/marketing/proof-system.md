# Proof System

The proof system exists to keep the brand honest while increasing conversion.

## Proof Types

1. Real product screenshots.
2. Public repositories and shipped deployments.
3. Architecture diagrams derived from the real system.
4. Metrics already present in `data/work/case-studies.ts`.
5. Permissioned testimonials and logos.
6. Case-study artifacts that can be shared during discovery.

## Placement Rules

- Homepage: only broad verified stats and the strongest product proof.
- Work pages: full proof board, screenshots, diagrams, build log, artifacts.
- Pricing: risk reversal, scope clarity, and proof near the CTA.
- Services: one service-specific diagram and one relevant case-study path.
- Blog: short proof blocks and route-specific CTAs.
- Academy: curriculum proof, not income claims.

## Missing Proof Register

- Founder photo: needed for `/founder`, homepage operator proof, newsletter avatar, and Academy.
- Permissioned testimonials/logos: use existing real Nexural proof only if permission and context are confirmed.
- Product screenshots: keep replacing concept frames with real screenshots as they are provided.
